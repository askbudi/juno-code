# Run task workflow

Own execution, semantic review, reviewed local integration, and safe cleanup for one exact existing workflow/task-set manifest. Reuse a creation-phase handoff from this request; otherwise require explicit artifact paths and never invent replacement tasks.

1. From the controller, resolve `controller_resolver.py --operation orchestration`; Juno never silently switches refs to manufacture a controller. Preflight authority, exact target/base identities, task IDs/dependencies, expected paths, budgets/timeouts, excluded E2E, immutable inputs/receipts, and fail-on-error behavior. Controller dirt is not a product integration gate.
2. For every product mutation, require a `worktree_lifecycle.py create` receipt proving a named exact-base task worktree. Product commands receive the explicit worktree root as `TASK_ROOT`; Kanban/session writes remain routed to the controller.
3. Lint local-integration workflows for one declared risk tier, `queue: automatic_after_review_pass`, `channel_scope: git_common_dir_and_target_ref`, `target_movement: rebuild_and_rereview`, and `checked_out_target: detach_same_sha`, plus validation ownership, typed integration receipt, terminal gate, and required receipt ordering. Executable preflight must call `integration_candidate.py target-preflight` for each official target; never hand-write target equality or parse arbitrary shell to guess ancestry semantics. Reject retired checkpoint-controller, clean-owner, repository-wide lease, or direct fast-forward integration shapes.
4. Run the declared controller `workflow_runner.sh` command once and wait. `--tmux` creates only an observer and does not detach the producer. Never deploy or run excluded E2E without separate authorization.
5. Require a `pre_merge` PASS receipt before deterministic candidate planning/building. Avoid standalone `implementation_guard`, `pre_merge_guard`, and `candidate_guard` steps: express those checks as typed receipt requirements and helper postconditions. Independently produce `candidate` PASS only when candidate composition creates bytes not already bound by the exact pre-merge review; direct unchanged candidates reuse the exact reviewed identity through deterministic verification. If the target moves, rebuild and re-review instead of reusing stale evidence.
6. Drain only an eligible candidate through a directly executed argv-list `integration_owner_preflight.py integrate` owner (optionally prefixed by `python3`), with declared risk and explicit same-command metadata detach policy; never use a shell command or wrapper for the integration step. Preserve active runtimes; report them current, stale behind target, or unknown. Require expected-SHA CAS and deterministic actual-target validation. Medium/high/release pre-merge review uses a fresh dedicated `yy pi` step with no resume; candidate review runs only for composition-changed bytes. Require semantic actual review and a feature tag for effective high/release; direct low/medium may skip both while recording explicit policy truth. Keep actual review inside integration and require its typed `actual_target_review` child evidence in Workflow Runner logs, response/capture/session/timing, checkpoints, manifests, recovery, doctor, and packets. Preserve conflicts, stale targets, partial updates, failed validation, and failed review without false success or cleanup. Resume partial multi-repository state only with `--resume-receipt` for the exact recorded operation.
7. Before any authorized local runtime or feature E2E, freeze and report the canonical checkout/ref/HEAD/gitlinks plus process CWD/PID; reject stale identity even when ports are healthy, and keep product-specific service controls outside Juno.
8. Inspect terminal steps, then run `task_workflow_helper.py finalize-review`. Compare the request/PDR, complete diff, receipts, Kanban readbacks, validation, target/tag identities, and worktree audit. Report runner exit, semantic verdict, local target, and remote/push state separately.
9. Resume only the smallest invalid stage. If terminal metadata is missing, first run `workflow_runner.sh recover-attempt RUN_DIR --dry-run`, then the mutating command; accept only its complete contiguous hash-bound prefix and resume exactly at the reported first invalid step. Recovery is interruption evidence, never semantic success. For a corrected harness contract, use a fresh out-dir with `--amends-run PRIOR_RUN --from-step STEP`; inspect the printed reuse/execute plan before dispatch. Cleanup is allowed only through the typed lifecycle helper after reachability and actual-target acceptance are proven.

Local integration grants no authority to push, publish, create a package-release tag, deploy, mutate production, or run post-deploy E2E.
